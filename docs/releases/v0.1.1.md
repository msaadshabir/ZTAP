# v0.1.1

Security and correctness fixes for the Kubernetes NetworkPolicy agent.

- Require non-host-network containers to drop `NET_RAW` or `ALL`, disable
  privilege escalation, and avoid privileged mode and added `NET_RAW` or
  `SYS_ADMIN`. The install manifest now includes a cluster-wide admission
  policy and binding, and the agent audits existing Pods before applying a
  snapshot. These restrictions prevent packet sockets from bypassing the
  cgroup packet hooks.
- Exclude `Succeeded` and `Failed` Pods from selector resolution so their
  retained IP addresses cannot authorize another Pod that reuses an address.
- Require each new TCP SYN to pass an explicit policy rule. Track FINs in
  both directions, expire closing state after 120 seconds without extending
  that interval, and clear state on reset while preserving half-closed streams.
- Preserve the policy epoch and established reply state when compiled map
  contents are unchanged, including retries after lifecycle publication errors.
- Serialize metrics collection and publication to prevent delayed snapshots
  from double-counting packet decisions, flow drops, and cleanup failures.

## Upgrade requirements

Update every non-host-network workload template, including system workloads,
init containers, sidecars, and debug containers, to satisfy the admission
restriction. Recreate existing unsafe Pods; admission does not change them
retroactively, and the agent refuses enforcement readiness while they remain.
Static Pods must satisfy the same restriction in their node-local manifests.

Install the attached digest-pinned `ztap-agent-v0.1.1.yaml` manifest to deploy
the new image and admission guard together. Keep both the admission policy
and binding installed. Workloads that need packet sockets or the prohibited
privileges are outside this enforcement profile.

Agent replacement still has the documented process-owned-link fail-open
interval. This release does not promise uninterrupted enforcement during an
upgrade. Fresh Linux amd64 and arm64 binaries, the multi-architecture image,
checksums, signatures, and release validation evidence are attached or linked
by the release workflow.
